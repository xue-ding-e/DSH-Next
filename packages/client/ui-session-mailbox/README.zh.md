# 会话信箱 UI

[English](README.md) | 中文

## 概述

向另一会话发送消息并查看收件箱。

## 目录

本文参考说明 Web 对话标题栏的信箱入口。它装配生成的[信箱 Remote 贡献](../../api/session-mailbox-controller/README.zh.md)，复用当前 Host 的 Session 列表，并在共享 modal 组件中将不可信消息渲染为文本节点。

<a id="mailbox-usage"></a>
## 显式交互

选择目标并输入正文后，确认仅排队发送。发送和读取都不会启动 Agent，运行中的目标不会被中断。打开面板不会读取收件箱；用户必须显式请求当前 Session 的收件箱，并单独确认已展示的收据。归档、删除和权限判断仍由 Host 执行，不只是 UI 过滤。

一次 UI 操作申请短时有效的精确路由 grant，准备一次不可变操作、消费句柄并释放 grant。关闭弹窗、切换选中的 Session 或连接重置都会中止交互；取消之后才返回的 grant 也会被撤销。重复点击不会产生并发提交。撤销和关闭都不会撤回已经提交的消息。

发送之前，UI 先将来源、目标、request id 和输入的正文保存到当前标签页的 `sessionStorage`，按端点 origin/path、新获取的逻辑信箱 realm 和 single-owner 域分区；key 不包含 query、fragment、URL 凭据或认证 token。这是有界重试状态，不是持久能力凭据。结果暂不可知时，重新打开面板或刷新标签页会恢复原草稿和请求标识；必须保持原内容核对后才能替换。存储仍可写时在核对成功后删除该状态；否则 UI 确认已投递，同时说明重试状态仍保留。浏览器禁止存储或配额不足时会阻止新发送，而不是在没有可恢复标识时继续发送。每个分区最多保留 32 个待核对草稿，每个正文上限为 16 KiB UTF-8。连接重置之后再次打开时重新获取身份；旧面板无法在不同 realm 上申请路由。身份获取失败时不打开草稿，恢复草稿也不会自动 prepare 或发送。其他标签页和新的浏览器会话不共享该恢复状态；状态丢失后应检查目标收件箱，不能将响应失败等同于未投递。

<a id="mailbox-implementation"></a>
## 使用限制

浏览器凭据代表账户所有者；标签页不是独立授权主体，UI 无法从密码学上证明发生了真人点击。Host 只接受真实 browser Peer，不接受 API operator 或模型自报的 owner 字符串。待核对正文保留在该标签页的浏览器存储中，直到核对成功或浏览器会话移除。取消 UI 选取不等于取消已经持久化的信箱收据。

Web bundle 装配此 UI 及其控制器。面向模型的路由授权通信、自动调度、附件、发件箱管理和 trigger-turn 执行不属于此 UI。组件测试覆盖显式选取、纯文本渲染、取消、重复点击和持久重试标识；生成 Gateway 契约及私有存储生命周期测试归控制器所有。打包后的浏览器启动和完整仓库检查仍是独立验收要求。

新建空白草稿在存储或申请路由之前拒绝。旧无效待核对草稿仍可保持原标识和正文重新核对。只有权威 `not-accepted` 响应才允许编辑；普通失败仍保持只读。完整 JSON 转义字节预算由 Host 按当前配置执行，不在浏览器通过原文字数猜测。

<a id="model-experience"></a>
## Model Experience

信箱文字仅供用户查看，不进入模型请求。

#### KV Cache effect

信箱操作不影响模型缓存。

## 已知限制与后续工作

- 仅限同一个配置档的所有者浏览器，支持文本和显式收件，不会自动启动会话。
